## 2. Bytes, not UTF-16

The reference lexes .NET's decoding of the file (`File.ReadAllText`): UTF-16, with ill-formed UTF-8 replaced by U+FFFD
per maximal subpart, and up to two leading BOMs dropped. CeeSafe lexes the bytes:
- one reference character is one UTF-8 sequence (`decodeUtf8`); an ill-formed subpart is one U+FFFD;
- string and char values, doc comments and the "unexpected character" message hold U+FFFD where the reference does;
- spans are byte offsets, converted to the reference's 1-based lines and UTF-16 columns when shown (`SourceText.position`).

**Known difference** (tested in `tests/syntax/lexer-known/`). After a backslash the reference steps over one UTF-16
unit. So in `"\😀"` the invalid escape's span ends between the surrogates, and the low surrogate is then lexed as the
next character of the literal. CeeSafe keeps the literal's value (U+FFFD for the lone surrogate) and the char literal's
recovery. Its span ends after the whole character, one UTF-16 unit later than the reference's. This only affects an
invalid escape of a character above U+FFFF.

## 3. How the lexer is checked

The reference has no token dump. `ceesafec parse --dump-tokens` prints the lexer's whole output: every token with its
UTF-16 span and value, the doc comments, the comments and the lexer's diagnostics. `tools/oracles/token-dump`, a .NET
program linked against the reference's `Nova.Compiler` at the pinned tag, prints the same from the reference's
`Lexer`. `tools/compare_tokens.py` runs both over a file set and compares their output byte for byte.

```sh
dotnet build tools/oracles/token-dump -c Release -p:NovaRoot=<Nova checkout at v0.4.1> -o <dir>
python3 tools/compare_tokens.py --ceesafec out/ceesafe --oracle <dir>/token-dump --root <Nova checkout> \
    lib tests/corpus programs benchmarks integrations site editors templates
python3 tools/compare_tokens.py --ceesafec out/ceesafe --oracle <dir>/token-dump --batch 1 tests/syntax/lexer
python3 tools/lexer_fuzz.py --random <dir>/fuzz 3000 20261030
python3 tools/compare_tokens.py --ceesafec out/ceesafe --oracle <dir>/token-dump --root <dir>/fuzz --batch 100 .
```

`tools/lexer_fuzz.py --cases` writes `tests/syntax/lexer/`. Its 21 edge cases cover:
- BOMs (one to three, and inside the text), line ends and form feeds;
- control bytes and NUL, every shape of ill-formed UTF-8, and non-ASCII outside literals;
- escapes, unterminated literals, and every number form and suffix error;
- all punctuation and keywords, doc and block comments, and empty input.

## 5. The AST

The reference's AST (`Ast.cs`) is a tree of immutable records with `ImmutableArray` children. CeeSafe follows P1's
pattern (`docs/p1-probes.md` §5): tables and indexes, with no references inside tables (`src/syntax/ast.nova`).
- **One table per syntactic category** in `Ast`: `exprs`, `stmts`, `types`, `patterns`, `items`, plus the smaller
  records (`idents`, `parameters`, `functions`, `structs`, `fields`, `variants`, `attributes`, `typeParameters`, arms,
  bindings, closures, field initialisers). Indexes are plain `u32`s; the field that holds one says which table it is
  in. (The design note proposed a struct per ID kind, but that was too verbose for the gain.)
- **A node is a `Copy` enum** whose payloads are indexes, small values and ranges, for example
  `Binary(u32, BinaryOp, u32)`. Its span is in a parallel table (`exprSpans[id]`). A node is read by copying it out.
- **Children lists** are a `Range` into one shared `lists` table. The parser collects a list in a local vector, then
  appends it in one run, so a range is contiguous even when nested lists are parsed in between.
- **Optional children** are `none()` (0xFFFFFFFF).
- **Text** (string values, docs, ABIs, float digits) lives in one byte table, referred to by ranges.
- Where the reference rebuilds a node with `with { … }`, for example to add attributes after an item is parsed or to
  widen a parenthesised type's span, CeeSafe changes the node in its table.

Symbols are interned in the reference's order, including the placeholders `<missing>`, `<extern>` and `<impl>`, the
keyword names `this` and `static`, and dotted struct-literal names. So identifier IDs, which later passes see, are
the reference's.

## 6. How the parser is checked

```sh
python3 tools/run_corpus.py --compiler out/ceesafe --reference ~/.nova/0.4.1/bin/novac --corpus <Nova>/tests/corpus \
    --family parse-pass --family parse-fail
python3 tools/compare_parse.py --ceesafec out/ceesafe --novac ~/.nova/0.4.1/bin/novac --root <Nova> \
    lib tests/corpus programs benchmarks integrations site editors templates
python3 tools/parser_fuzz.py <dir>/mut 3000 20261030 <Nova's lib and corpus files>
python3 tools/compare_parse.py --ceesafec out/ceesafe --novac ~/.nova/0.4.1/bin/novac --root <dir>/mut .
```

`compare_parse.py` runs `parse --dump-ast --diagnostics-format=json` and `parse` (text diagnostics) with both
compilers. It requires the same exit status, stdout and stderr: the tree, every diagnostic's message, both ends of its
span, its fix, the rendered excerpt and caret. `parser_fuzz.py` breaks real files (deleting spans and lines,
duplicating and swapping lines, inserting token fragments, cutting the file short) to drive the recovery paths.

**Where the reference recurses without a limit.** N0110's nesting limit counts blocks, statements, types, patterns,
unary operands and each link of a left-associative chain. Three chains are not counted:
- `else if` in `if` statements;
- `else if` in `if` expressions;
- the `?` suffixes of `T???…`.

The reference recurses through them on its 256 MiB compiler stack. Its AST printer, which runs on the main thread,
aborts on a 20,000-link `else if` chain. At 100,000 links it times out, because the dump's indentation makes the output
quadratic. CeeSafe builds and prints these three chains in loops, with the same nodes in the same order, so it does not
depend on stack size. The output is identical wherever the reference finishes. Proposed upstream: count these links
toward N0110, as grammar.md §2.2 intends (not yet filed).
